# Agent Note: 右侧 Sidebar chrome 几何

Status: implemented

[English](2026-09-09-right-sidebar-chrome-geometry.md) | 中文

## Problem

右侧 Sidebar 首次打开时占用框架的 45%，在常见桌面宽度下压迫会话区。打开后，会话 header 的开关被 68px 空占位替换，形成明显的无效区域。会话 header 与 Sidebar 标签条还使用不同的高度和边框机制，两列的共享边缘无法对齐。

## Decision

右列首次打开偏好调整为实测框架宽度的 35%，并继续受既有 300px 下限和 70% 上限约束。用户拖拽设置的像素偏好在关闭、重开与窗口缩放间继续作为权威值。

会话 header 控件在面板的两种状态下都保持挂载。它的无障碍名称在展开与收起之间切换，同一开关动作更新会话作用域的 Sidebar 状态。固定的 68px × 32px 区域在不渲染空占位的前提下保持相邻 header 工具稳定。

会话 header 与 Sidebar 标签条都使用明确的 56px border-box 高度和同一条 0.5px `border-l3` 底边框。两个组件仍分别保留自己的内容间距与控件，只统一共享外层几何。

## Alternatives considered

**保留 45% 默认值并依赖用户拖拽。** 否决，因为首次打开体验本身就是产品行为，而用户拖拽后的显式像素偏好已经会被保留。

**保留空占位，只允许从面板内收起。** 否决，因为 header 表达了稳定的面板位置，却在面板可见时删除其操作。

**使用独立伪元素对齐两个 header。** 否决，因为在两个 56px border box 上各声明一条边框更简单，也不会因不同定位机制产生亚像素偏移。

## Consequences

新右栏以更克制的桌面比例打开，且不改变已存储的用户选择。会话 header 始终提供一个面板开关，两列 header 共享同一底部坐标与分隔线 token。聚焦的布局与开关测试锁定新默认值和控件两种状态；组装 UI 检查在支持的桌面宽度下比较实际渲染几何。
